Verified discovery
- Current authenticated API on loopback port 8642 exposes /api/model/options,
  /v1/models and POST /api/sessions/{id}/model. Model inventory includes
  unconfigured providers and optimistic reasoning flags: those alone are not proof
  of usable routes, vision support or supported effort/disable levels.
- /v1/models currently advertises only hermes-agent. The configured model is
  accounts/fireworks/models/deepseek-v4p1-flash; Fireworks reports authenticated.
- The existing model-lock endpoint persists browser_model_lock in the session
  model_config. Durable /v1/runs must be checked separately: its current launch
  path does not pass confirmed_runtime_lock into _create_agent.
- Browser artifact transport is feature-gated, bounded to 10 MiB, expires in
  300 seconds and consumes an artifact on its first download. It cannot back
  persistent attachments. A separate capability-gated persistent store is needed.
- Existing tools.file_tools.read_file already extracts PDFs/documents through
  tools.read_extract. Preserve original bytes and let paginated file tools read
  documents; no new extraction dependency or unlimited prompt text injection.
- AIAgent.run_conversation accepts multimodal user_message and a separate
  persist_user_message, allowing real image input without raw base64 in chat UI.
- The user clarified GPU telemetry is local to the Hermes plugin's server, using
  amd-smi or the NVIDIA equivalent. No Moe/SSH access is required. The previously
  supplied web service is a Qwen chat UI and is not an app telemetry dependency.
- Installed Hermes supports ctx.register_platform_handler("api_server", factory).
  The factory receives the aiohttp application before its router freezes, enabling
  authenticated plugin endpoints without adding a second listening port.

Implementation constraints
- Keep the existing API origin and bearer boundary; never expose upstream keys.
- Profiles isolate local files, drafts, selection and all asynchronous callbacks.
- Persist exact model options and attachment IDs in the run journal before POST;
  retry never changes those fields or mints a new admission identity.
- Unknown model capabilities remain unavailable/unknown. Do not silently switch
  providers, invoke a separate vision model or equate minimum reasoning with Off.
- Artifact IDs are opaque; downloads are authenticated and repeatable. Validate
  byte limits, metadata, scope and traversal. Generated artifacts come from a
  bounded session output directory, not arbitrary filesystem paths from the UI.
- Copy granted content-provider streams into app-private storage for draft
  durability. FileProvider grants only the selected share-out item. Preserve
  source bytes; exclude local files, keys and phone captures from Git/releases.
- Use existing libraries plus Android APIs (Storage Access Framework, PdfRenderer,
  FileProvider and Sharesheet). No new dependency is planned.
