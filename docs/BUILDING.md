# Build the experimental preview

The preview source is on `repair/experimental-open-issues`, with immutable development
release tags. The default branch has the earlier app code and an updated front
page; it is not the source of the 0.8.3 APK.

## Get all source files

Use a recursive clone of the release tag:

```bash
git clone --branch android-v0.8.3-integration-preview.1 --recurse-submodules \
  https://github.com/PraxisOG/Bellpull.git
cd Bellpull
git submodule status --recursive
```

For an existing checkout, fetch the tag, check it out, then run
`git submodule update --init --recursive`. There are three pinned native trees:

| Source | Exact revision |
| --- | --- |
| [qwentts.cpp](https://github.com/ServeurpersoCom/qwentts.cpp) | `51512f129a7419567f4b8abfb06801451789b8f1` |
| Its nested [GGML](https://github.com/ServeurpersoCom/ggml) | `2eddaf94a8cdbbf1c30017d28313cd661a9da543` |
| [Sherpa-ONNX](https://github.com/k2-fsa/sherpa-onnx) | `11afbd009a7f8c08f4bcf2fc1b265d0df4670fbf` (1.13.8) |

All revisions are publicly fetchable. GitHub's automatic source ZIP/tarballs do
**not** include submodule contents. Use the recursive clone above, or download the
release's **Bellpull-source-0.8.3.tar.gz**, which includes tracked source and all
three native trees. That archive also contains `SOURCE-REVISIONS.json`.

```bash
tar -xzf Bellpull-source-0.8.3.tar.gz
cd Bellpull-0.8.3
```

## Toolchain

Use JDK 21, Python 3, and an Android SDK with command-line tools. Set `ANDROID_HOME`
to your SDK directory, then install the same packages as CI:

```bash
sdkmanager 'platform-tools' 'platforms;android-37.0' 'build-tools;37.0.0' \
  'ndk;29.0.14206865' 'cmake;3.31.6'
```

Accept the SDK licenses with the normal SDK manager workflow. The tracked Gradle
wrapper downloads Gradle. A first build needs network access for Maven dependencies
and CMake's pinned downloads; subsequent builds can use the dependency cache.

Moonshine CPU SDK 0.1.5 comes from Maven. Pocket's ONNX Runtime static libraries
(1.28.2, ARM64 and x86_64) and nlohmann/json 3.12.0 are downloaded by the tracked
CMake file with SHA-256 verification. Pocket adapter sources and Qwen's version
header are generated by tracked build scripts. No local AAR, prebuilt Bellpull
library, personal directory, server credentials or downloaded speech model is
required to compile. Speech weights are downloaded separately inside the app.

## Build and validate

From the repository/archive root:

```bash
./android/gradlew -p android assembleDebug lintDebug
./android/gradlew -p android test verifyRoborazziDebug
```

The debug APK is `android/app/build/outputs/apk/debug/app-debug.apk`.
`./android/gradlew -p android assembleRelease` builds an unsigned release when
private signing configuration is absent. Use your own signing key for your own
installation. Official signing keys, passwords, local SDK paths and caches are
deliberately excluded; they are not missing build source. A debug/independently
signed APK cannot be assumed to update the official installed app.

Tests run without a Hermes provider or personal phone. Keep live inference smoke
tests opt-in. Instrumentation must use `-PbellpullDeviceFixture=true` and the
disposable fixture package; some tests clear credentials.

## Source verification

Current release evidence is in [the 0.8.3 release record](RELEASE-0.8.3-EXPERIMENTAL.md).
The historical source checks below describe the earlier integration release.

A fresh GitHub clone of the first 0.8.1 tag successfully fetched every recursive
submodule and built `assembleDebug lintDebug` with no local source files or signing
configuration. It used the installed SDK/shared dependency cache. The source/CI
follow-up pins screenshot fixture timezones and adds an explicit older-host
rejection case; it does not change production app code or the signed APK.

The coding CI job uses a pinned modern stock Hermes image with native output
tracking. The separate legacy compatibility job keeps its pinned host, verifies
that unsupported coding activity is declined, and still runs the approval suite.
No failing check is converted to success and screenshot baselines are unchanged.
