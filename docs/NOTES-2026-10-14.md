# Winston's notes — 2026-10-14

Two items on the Bellpull backlog, captured verbatim in intent, plus initial triage.

## 1. Bug: voice mode's first message becomes the chat title

**Report:** If voice mode is on for the very first message of a new chat, the
chat gets titled with the voice-mode instruction text (the spoken-reply
preamble) instead of something meaningful.

**Triage:** Chat titles are derived from the first user message. Voice turns
arrive wrapped in a one-paragraph spoken-reply instruction (see
VOICE-PROMPT-DISCLOSURE.md), so the raw instruction leaks into the title.
Likely fix locations:

- Server side: title generation from the first message should strip/ignore the
  voice-mode instruction wrapper before titling (check the bellpull plugin's
  session/title handling, and how the voice preamble is attached —
  `plugins/bellpull/` voice path).
- App side: if titling happens in the app when creating the session, use the
  transcribed user text, not the composed instruction payload.

Whichever side owns titling, the rule is: the voice instruction wrapper is
chrome, never content — it must not reach the title.

## 2. Feature idea: long-press agent message → info panel

Long-press an agent message to reveal an info button/sheet showing per-turn
stats: how long the agent worked (duration), tokens read (input), and tokens
written (output).

**Triage:** Requires the plugin to surface per-turn usage/duration on the
message payload (Hermes records token usage per completion; check what the
gateway exposes and whether the bellpull API contract in `docs/hermes-api.md`
needs a new field). App side: Compose combined-long-press on the message row +
small info sheet. Add any needed fields to `docs/hermes-api.md` first — it is
the only source of truth for the contract.
